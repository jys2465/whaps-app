# 화프스(WHAPS) v5.0 설치·사용 안내

WHITE PRICE 운영 시스템입니다. 화면은 GitHub Pages, 서버는 구글시트에 붙은 Apps Script, 파일은 구글 드라이브에 둡니다.

## 0. v4.0에서 v5.0으로 올리기

v5는 설계안 v8(운영 프로세스·업무 정의·시스템 설계안)을 반영한 판입니다. 기존 시트를 그대로 쓰고, 자료는 자동으로 옮깁니다.

1. **구글시트 사본을 먼저 만듭니다**(파일 → 사본 만들기). 문제가 생기면 되돌릴 수 있게 하기 위해서입니다.
2. **Apps Script**: `Code.gs`와 `Templates`를 새 파일 내용으로 모두 바꿔 붙여 넣고 저장합니다.
3. **`setup`을 한 번 실행**합니다. 실행 로그에서 이전 결과를 확인하세요.
   - 시트 4개(재고수불·광고측정·광고클릭·PG정산)와 설정 4개(기본출고창고·정산차이_반올림·재고마감월·광고링크주소)가 생깁니다.
   - 상품·주문의 배송방식이 **운영방식**으로 바뀝니다(자사배송 → 재고형, 업체배송 → 주문형).
   - 창고 **W01은 가상창고**로 고정됩니다. 예전에 W01을 실제 창고로 썼다면 새 번호(W02~)로 옮기고, 매입·상품의 창고 번호도 함께 바꿉니다.
   - 벤더의 대금 지급주기가 4종(월 1~4회)으로 바뀝니다. 비어 있으면 직매입 월 4회, 위탁판매 월 2회입니다.
   - 관리자가 고친 계약서 양식의 적용 조건도 재고형·주문형으로 바뀝니다.
4. **배포 → 배포 관리 → 수정 → 새 버전 → 배포**를 누릅니다(주소는 그대로).

5. **GitHub**: `app.js`, `app.css`, `templates.js`를 바꾸고 **`go.html`을 새로 올립니다**(광고 추적 링크).
6. 오픈 전 시험 주문·매입·정산을 지우려면 Apps Script에서 **`clearTestOps`**를 한 번 실행합니다. 그다음 매입 화면에서 **기초재고**를 한 번 등록합니다.
7. 더보기 → 회사 정보와 기준값에서 **광고링크주소**에 `https://아이디.github.io/저장소/go.html`을 넣습니다(성과형 광고가 있을 때).

## 2. 설치 (처음 한 번, 약 20분)

### 2-1. 새 구글시트에 서버 넣기

1. 구글 드라이브에서 **새 스프레드시트**를 만들고 이름을 `WHAPS_DB_v4`로 정합니다. 기존 `WHAPS_DB_v3`와 섞지 않기 위해서입니다.
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 기본 파일 `Code.gs`의 내용을 모두 지우고 `apps-script/Code.gs`를 붙여 넣습니다.
4. 왼쪽 **파일 +** → **스크립트**로 `Templates`라는 파일을 만들고 `apps-script/Templates.gs`를 붙여 넣습니다.
5. 저장(Ctrl+S)한 뒤, 위쪽 함수 목록에서 **`setup`**을 고르고 **실행**을 누릅니다.
6. 권한 요청 창이 뜨면 본인 계정으로 **허용**합니다. "확인되지 않은 앱" 경고가 나오면 **고급 → (안전하지 않음)으로 이동**을 누릅니다. 내가 만든 스크립트라 괜찮습니다.
7. 실행 로그에 `첫 관리자 아이디: admin   임시 비밀번호: xxxxxxxxxx`가 나옵니다. **임시 비밀번호를 적어 둡니다.**
8. 시트에 탭 10개(사용자, 공지, 분류, 창고, 벤더, 상품, 계약, 계약첨부, 감사로그, 설정)가 생겼는지, 드라이브에 `WHAPS` 폴더가 생겼는지 확인합니다.

### 2-2. 웹앱으로 배포

1. Apps Script 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 유형 선택(톱니) → **웹 앱**을 고릅니다.
3. **다음 사용자 인증 정보로 실행: 나**, **액세스 권한이 있는 사용자: 모든 사용자**로 정합니다.
   화면이 로그인 전에 서버를 불러야 하므로 '모든 사용자'가 필요합니다. 데이터는 로그인 토큰이 없으면 열리지 않습니다.
4. **배포**를 누르고 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.

### 2-3. GitHub 저장소에 화면 올리기

1. 저장소에서 **기존 `whaps_auth.js`, `whaps_data.js`, `whaps_main.js`, `whaps_sync.js`를 삭제**합니다. 특히 `whaps_auth.js`에는 PIN이 들어 있습니다.
2. 이 묶음의 화면 파일 7개(`index.html`, `app.js`, `app.css`, `templates.js`, `config.js`, `gcw1.png`, `wp1.png`)와 `vendor` 폴더를 올립니다.
3. `config.js`를 열어 `API_URL`에 2-2에서 복사한 웹 앱 URL을 넣고 커밋합니다.
4. 1~2분 뒤 GitHub Pages 주소로 접속하면 로그인 화면이 나옵니다.

### 2-4. 첫 로그인과 초기 설정

1. 아이디 `admin`, 임시 비밀번호로 로그인하면 비밀번호 변경 화면이 나옵니다. **영문과 숫자를 섞어 8자 이상**으로 바꿉니다.
2. **더보기 → 회사 정보와 기준값**에서 회사 상호·사업자번호·대표자·주소를 확인합니다. 여기 값이 모든 계약서의 '공급받는 자' 칸에 들어갑니다. 사업장 주소 정정신고를 하면 여기만 고치면 됩니다.
3. **더보기 → 사용자 관리**에서 직원 계정을 만듭니다. 계정을 만들면 임시 비밀번호가 **한 번만** 보이니 본인에게 직접 전달하세요. 첫 로그인 때 각자 바꾸게 됩니다.

## 3. 계약서

### 압축한 계약서 (본문 3쪽 이내)

- 상품공급계약서는 **한 양식에 조항마다 적용 조건**(직매입·위탁판매·제휴입점, 재고형·주문형)이 붙어 있습니다. 계약을 만들 때 상대방의 거래형태와 고른 배송방식에 해당하는 조항만 들어가고, 조항 번호는 자동으로 다시 매깁니다.
- 별지 1 거래조건표는 공급사의 상품 정보(판매대기·판매중·판매보류)로 만들어 본문 뒤 한 쪽에 붙습니다.
- 계약 작성 화면 오른쪽 위에 "계약서 본문 ○쪽 + 별지 ○쪽"이 표시되고, 3쪽을 넘으면 경고합니다. 시험한 결과는 직매입(자사+업체)·위탁판매 3쪽, 제휴입점 2쪽입니다.
- 계약 종류: 상품공급계약, 거래조건표 변경, 판촉 약정, 독점판매 특약, 광고 게재(추가), PB 제조 하도급, 물류(3PL) 위탁, IT 개발·유지보수.

### 계약서 양식 관리 (관리자)

- 더보기 → **계약서 양식 관리**에서 양식을 고릅니다. 조항마다 제목·적용 조건·본문을 고치고, 위아래로 옮기고, 지우고, 새 조항을 넣을 수 있습니다.
- 본문은 한 줄이 한 문단입니다. ①②로 항을, "1. "로 목록을, `| 칸 | 칸 |`으로 표를 만듭니다.
- 입력값은 `{{이름}}`으로 씁니다. 목록에 없는 이름을 쓰면 계약 작성 화면에 그 이름의 입력칸이 새로 생기고, 확정할 때 빈칸이면 확정되지 않습니다.
- 저장하면 새 판(v1, v2…)이 되고 이력에 남습니다. **기본 양식으로 되돌리기**도 새 판으로 저장됩니다.
- 이미 확정된 계약은 **확정할 때의 양식을 함께 보관**하므로, 양식을 고쳐도 바뀌지 않습니다(전자서명본도 그 양식으로 만듭니다).

### 입력값

- **선택**: 운영기획이 정한 목록에서 고릅니다. PL 보험 보상한도는 목록 외에 "해당 없음"과 "직접 입력"도 됩니다.
- **입력**: 회색 글씨가 입력 예시입니다. 금액 칸은 숫자만 넣으면 쉼표가 붙습니다.
- **자동**: 상대방 정보(벤더 마스터), 거래형태, 광고료 계산, 거래조건표 번호(확정 때 계약번호).

### 서명: 전자서명 또는 종이

**전자서명 (업체는 휴대폰에서)**
1. 계약 화면에서 **업체에 전자서명 요청**을 누릅니다. 업체 계정이 없으면 만들어지고(아이디는 벤더 코드, 예: v0001), 임시 비밀번호와 안내 문구가 나옵니다. **안내 문구 복사**를 눌러 담당자에게 문자나 메신저로 보냅니다.
2. 업체 담당자가 휴대폰으로 로그인해 새 비밀번호를 정하고, **서명할 계약**에서 내용을 확인한 뒤 두 가지 동의에 체크하고 손가락으로 서명합니다. 사업자등록증·통장사본도 사진으로 바로 올릴 수 있습니다.
3. 회사 쪽은 **회사 직인으로 서명**(등록한 직인 이미지) 또는 **직접 서명**을 누릅니다. 순서는 상관없습니다.
4. 양쪽 서명이 끝나면 서명 이미지가 각 문서의 대표자 칸에 들어간 **전자서명본 PDF**와 마지막 쪽의 **전자서명 확인서**(원본 PDF 지문, 서명자·시각·계정)가 자동으로 만들어지고, 서명본으로 등록·확인됩니다. 계약 체결일은 늦게 서명한 날입니다.

**종이**: 지금처럼 PDF를 출력해 양쪽이 계약일을 적고 서명·직인한 뒤, 스캔본을 올리며 늦게 서명한 날짜를 체결일로 입력합니다.

서명이 끝나면 필요한 서류(기본계약·PB·3PL·IT는 서명본·사업자등록증·통장사본, 제휴입점 기본계약은 통장사본 제외, 별지·광고 게재는 서명본만)를 확인하고 **계약 완료 처리**를 누릅니다.

## 4. 상품 · 분류

### 상품 상태

| 상태 | 뜻 | 누가 정하나 |
| --- | --- | --- |
| 판매대기 | 등록했지만 아직 몰에 보이지 않음(전시 대기) | 등록하면 자동 |
| 판매중 | 몰에 보이고 주문할 수 있음(전시·판매) | 운영기획·관리자 |
| 판매보류 | 일시품절·재고 확인 등으로 잠시 팔지 않음 | 운영기획·관리자 |
| 판매종료 | 더 이상 취급하지 않음(단종) | 운영기획·관리자 |
| 삭제대기 | 삭제를 요청함 | MD도 요청 가능 |
| 삭제 | 삭제됨(목록에서 숨기고 기록은 남김) | 운영기획·관리자(삭제대기를 거쳐야 함) |

- 상품 목록 위의 상태 단추로 걸러 봅니다. "전체"에는 삭제한 상품이 빠집니다.
- 분류 화면의 각 분류에는 하위 분류까지 합친 상품 수가 상태별로 나옵니다. 분류의 체계버전은 없앴습니다.
- 금액·수량 칸은 오른쪽 정렬되고 천 단위 쉼표가 자동으로 붙습니다(저장할 때는 숫자만 저장).

### 엑셀

- 화면마다 **엑셀 서식 안내**를 펼치면 내려받는 파일의 모양(데이터 시트 + 작성 안내 시트, 1행 칸 이름)과 올리는 규칙이 나옵니다.
- 내려받을 때 금액·수량은 숫자 서식(#,##0)으로 나옵니다. 올릴 때는 쉼표가 있어도 됩니다.
- 한 행이라도 틀리면 아무것도 저장하지 않고, 틀린 행 번호와 이유를 보여 줍니다.

## 5. 운영: 주문 → 매입 → 재고 → 정산 → 손익

### 기준 (설계안 v8)

| 거래 | 매입 | 매출·원가 | 공급사 정산 기준일 |
| --- | --- | --- | --- |
| 재고형 직매입 (DS) | 센터입고일(검수 합격 수량) | 송장발행일, 원가 = 이동평균 단가 | 센터입고일 |
| 주문형 직매입 (DO) | 송장발행일(자동) | 송장발행일, 원가 = 그 매입 단가 | 송장발행일 |
| 재고형·주문형 위탁 (CS·CO) | 없음(공급사 소유) | 송장발행일, 수수료 매출 | 송장발행일 |
| 제휴입점 (AF) | 없음 | 정액은 게재 일수로 나눠 월별, 성과형은 측정한 달 | 광고료 청구 |

- **송장발행일 = 아임웹 주문 엑셀의 배송일자**입니다(고객이 받은 날과 무관). 처음 들어온 값으로 고정하고, 바뀌면 안내만 합니다.
- **반품**은 아임웹 반품완료일에 마이너스 매출·원가로 처리합니다. 재고형 양품은 보관창고로 돌아가고, 주문형은 마이너스 매입이 됩니다.
- **구매확정일**은 기록만 합니다(매출·정산에 쓰지 않음).

### 창고: 실제 보관창고(W02~)와 가상창고(W01)

- 재고형 상품은 **실제 보관창고(W02~)**에 두고 이동평균 단가로 재고금액을 계산합니다.
- 주문형 직매입 상품은 송장발행일에 **가상창고(W01)**로 들어오고(매입) 같은 날 나갑니다(매출원가). 반품도 같은 날 들어왔다가 공급사 반품으로 나갑니다. 그래서 **가상창고 잔액은 매일 0**이어야 합니다.
- 하루라도 0이 아니면 매입과 매출원가 중 한쪽이 빠진 것입니다. 홈·재고·데이터 점검에 **오류**로 나오며, 그날 바로 고칩니다.

### 주문 (아임웹 엑셀, 매일 또는 정산일 오전)

1. 아임웹 관리자 → 주문 관리 → 엑셀 다운로드(품목 단위 권장).
2. **운영 → 주문 → 아임웹 주문 엑셀 올리기**. 칸 이름을 자동으로 맞춥니다. **배송일자(송장발행일)는 꼭 맞춰 주세요.**
3. 주문상태 맞추기 → 미리보기(송장발행·반품완료·배송일자 없음·배송일자 바뀜 건수) → 저장.
4. 저장하면 주문형 매입, 가상창고, 보관창고 재고, 출하원가가 함께 계산됩니다. 한 번에 5,000줄까지 올립니다.
5. 주문 조회는 주문일 또는 배송일자 기준으로 300줄씩 받습니다("다음 300줄 받기").

### 매입

- **입고 매입(재고형)**: 공급사·입고일(센터입고일)·보관창고·상품·수량(검수 합격)·단가. MD가 등록하고 운영기획이 확정하면 재고와 정산에 들어갑니다.
- **기초재고**: 오픈 전 한 번, 실사 수량으로 등록합니다(정산에는 들어가지 않음).
- **자동 매입(주문형)**: 송장발행일에 자동으로 생기며 "자동 매입 (주문형)" 탭에서 봅니다. 단가는 처음 매입한 때의 공급가로 고정됩니다.

### 재고

- 상품별 창고 수량, 회사·위탁 재고, 이동평균 단가, 재고금액, 가상창고 잔액을 봅니다.
- **실사**: 센 수량을 넣으면 장부와의 차이를 기록합니다. 사유는 3PL 귀책(계약대로 배상 청구) / 파손·불량 / 기타.
- **조정**, **위탁 입고**(위탁판매 재고형), 수불부 보기, 수동 기록 지우기.
- **월 재고 마감**: 월말 실사를 마치고 가상창고가 매일 0인지 확인한 뒤 지난달을 마감합니다. 마감한 달은 다시 계산하지 않아 빨라집니다. 마감 뒤에 늦게 들어온 그달 주문은 **마감 다음 날**로 들어가고 메모가 남습니다. 마감 풀기는 관리자만 합니다.

### 정산 (지급일별)

- **지급월과 지급일(7·14·21·28일)**을 고르면 공급사마다 지급주기에 맞는 마감 기간을 찾아 모읍니다. 그 날짜에 지급하지 않는 공급사는 따로 알려 줍니다.

| 지급주기 | 마감과 지급일 |
| --- | --- |
| 월 1회 | 1일~말일분 → 다음 달 7일 |
| 월 2회 | 1~15일분 → 21일, 16일~말일분 → 다음 달 7일 |
| 월 3회 | 1~10일분 → 21일, 11~20일분 → 28일, 21일~말일분 → 다음 달 7일 |
| 월 4회 | 1~7일분 → 14일, 8~14일분 → 21일, 15~21일분 → 28일, 22일~말일분 → 다음 달 7일 |

- 지급일이 휴무일이면 **다음 영업일**입니다(설정의 공휴일 목록).
- 정산 금액은 **아임웹 금액**입니다. 상품 판매가로 계산한 금액과 다르면 줄마다 차이 사유(할인·쿠폰, 옵션 가격, 판매가 변경, 회원가 적용, PG 결제수단, 반올림 차이, 기타)를 넣어야 확정됩니다. 10원 미만은 "반올림 차이"로 자동 등록됩니다.
- 지급한 위탁 판매분이 반품되면 다음 회차에서 뺍니다. 뺄 지급액이 없으면 정산서 지급액이 마이너스가 되고, **공급사에 반환 청구**(14일 이내) 안내가 나옵니다.
- 광고료: 기간 정액은 게재 시작일 전날까지, 성과형은 확정한 달을 다음 달 10일까지 청구합니다.

### 손익

- 매출 − 매출원가 = **상품이익**, − PG수수료(표준 3.63%) = **공헌이익**, − 비용 = **영업이익**.
- 재고 검산: 기초재고 + 매입 − 매출원가 + 반품 재입고 ± 조정 = 기말재고(보관창고). 장부 재고와 같으면 "맞음".
- **토스 정산 엑셀**을 월 1회 올리면 그달 PG 실제 금액과 표준과의 차이를 보여 줍니다.

### 광고 성과 (제휴입점 성과형)

- 클릭은 화프스 추적 링크(`go.html?a=계약번호&p=상품코드`)로 셉니다. 같은 기기의 24시간 안 반복 클릭, 자동 프로그램, 화프스에 로그인한 기기의 접속은 무효입니다.
- 달이 끝나면 노출수(노출당)·판매금액(판매당)을 넣고 확정합니다. 월 예산 상한을 넘으면 상한까지만 청구합니다. 공급사 보고 클릭(UTM)은 비교용입니다.

### 데이터 점검

매일 주문을 올린 뒤 실행합니다. 가상창고 잔액이 0이 아닌 날, 재고 음수, 송장은 있는데 배송일자 없는 주문, 바뀐 배송일자, 반품완료일 없는 반품, 미연결 주문, 몰상품코드 중복, 공급가·수수료율 없는 상품, 오래된 미확정 매입, 작성 상태·차이 사유 없는 정산서, 반환을 청구할 위탁 정산서, 계약 없이 판매 중인 공급사, 이번 달 실사 차이를 보여 줍니다. 항목을 펼치면 자세한 목록이 나옵니다.

### 속도를 위해 바꾼 점

- **한 번 읽기**: 요청 하나에서 같은 시트는 한 번만 읽습니다(주문을 올리면 주문·매입·재고 계산이 같은 자료를 함께 씀).
- **바뀐 줄만 쓰기**: 시트 전체를 다시 쓰지 않고 바뀐 줄만 씁니다. 주문 시트는 올리기 한 번에 한 번만 씁니다. 매입 입고·확정도 줄마다 쓰지 않고 한 번에 씁니다.
- **캐시 나누기**: 계약·상품 등 기본 자료와 주문·재고 등 운영 자료의 캐시를 따로 둡니다. 주문을 올려도 앱을 여는 속도(기본 자료)는 그대로입니다.
- **조회 결과 기억**: 손익·데이터 점검·재고·주문 조회 결과는 서버가 자료가 바뀌기 전까지(최대 1시간) 기억해 두고, 화면도 바로 그린 뒤 뒤에서 새로 받습니다.
- **재고 마감**: 마감한 달은 다시 계산하지 않습니다.
- **나눠 보기**: 주문은 300줄씩 받고, 긴 표는 100줄씩 그립니다.
- 시험 결과(구글 모형, 월 3,000줄 × 6개월): 주문 올리기 한 번에 쓰는 칸 수가 약 37% 줄었고(33만 → 21만 칸, 6개월째에도 늘지 않음), 같은 손익·점검을 다시 열 때는 시트를 읽지 않습니다. 실제 구글시트에서는 주문 1만 줄대까지 올리기 10~20초 안팎을 예상합니다.
- 주문이 해마다 3만 줄을 넘게 쌓이면 시트 칸 수(1천만 칸 한도)와 읽기 시간이 늘어납니다. 그때는 지난 해 주문을 별도 보관 시트로 옮기는 기능을 추가하는 것을 권합니다.

## 6. 코드를 고친 뒤 다시 배포하기 (중요)

Apps Script를 고친 뒤 **새 배포**를 누르면 주소가 바뀝니다. 주소를 그대로 두려면
**배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**를 누르세요. 그러면 `config.js`를 고칠 필요가 없습니다.

## 7. 보안 점검 목록

- [ ] 예전 Apps Script(v3) 웹앱은 **배포 관리 → 보관처리**로 끕니다. 예전 주소는 인증 없이 데이터를 읽고 쓸 수 있습니다.
- [ ] 예전 코드에 적혀 있던 PIN은 노출된 것으로 보고 다시 쓰지 않습니다.
- [ ] 구글시트와 드라이브 `WHAPS` 폴더는 **링크 공유를 끄고**, 편집자는 관리자 1~2명만 둡니다. 직원은 시트를 직접 열지 않고 화프스 화면으로만 일합니다.
- [ ] GitHub 저장소가 공개라면 비공개로 바꿀지 결정합니다. 화프스 화면 코드에는 비밀이 없지만, 커밋 기록에 예전 주소와 PIN이 남아 있습니다.
- [ ] 개인정보(통장사본 등) 보관기간은 세무사·법률 검토로 정합니다.
- 업체 계정(역할 "업체")은 연결된 벤더의 확정된 계약만 보고, 서명과 사업자등록증·통장사본·PL보험증권 올리기만 할 수 있습니다. 벤더·상품·다른 업체 계약·내부 메모는 서버에서 막습니다.
- 업체 임시 비밀번호는 발급할 때 한 번만 보입니다. 안내 문구는 담당자 본인에게만 보내세요.
- 주문 엑셀에서 고객 이름·연락처·주소는 저장하지 않습니다(주문번호·상품·수량·금액·상태·날짜만).
- 정산·손익·비용은 운영기획·관리자만 봅니다. 계약서 양식은 관리자만 고칩니다.

## 8. 문제가 생기면

| 증상 | 확인할 것 |
| --- | --- |
| "config.js에 Apps Script 웹앱 주소를 넣어 주세요" | `config.js`의 `API_URL`이 `…/exec`로 끝나는 웹앱 주소인지 |
| "서버에 연결하지 못했습니다" | 배포 액세스가 '모든 사용자'인지, 주소를 정확히 복사했는지 |
| "로그인이 만료되었습니다" | 로그인 후 6시간이 지나면 다시 로그인해야 합니다 |
| "비밀번호를 5번 틀려 잠겼습니다" | 15분 기다리거나, 관리자가 **비밀번호 초기화**를 해 줍니다 |
| "시트가 없습니다. setup()을 먼저 실행하세요" | Apps Script에서 `setup`을 실행했는지 |
| PDF 글꼴이 Noto Sans KR이 아님 | 구글 문서에 Noto Sans KR이 없으면 기본 글꼴로 바뀔 수 있습니다. 첫 PDF에서 꼭 확인해 주세요 |
| PDF 아래 로고가 없음 | 더보기 → 회사 정보와 계약서 로고에서 등록 상태를 확인하세요. 로고가 없어도 PDF는 만들어집니다 |
| "엑셀 기능을 불러오지 못했습니다" | GitHub에 `vendor/xlsx.full.min.js`가 올라갔는지 확인하세요 |
| 업체가 "연결된 업체 정보가 없습니다"라고 나옴 | 사용자 관리에서 그 업체 계정의 벤더 연결을 확인하세요 |
| 확정할 때 "빈 칸이 있습니다: 상대방 담당자…" | 벤더 정보에 담당자·연락처·이메일·주소·대표자를 먼저 채우세요 |
| "벤더의 거래형태를 먼저 정하세요" | 마스터 → 벤더에서 구분이 공급사인 벤더의 거래형태(직매입·위탁판매·제휴입점)를 정하세요 |
| 회사 직인으로 서명 버튼이 흐림 | 더보기 → 회사 정보·선택 목록·로고·직인에서 직인 이미지를 먼저 올리세요 |
| 주문 미리보기에서 "알 수 없는 주문상태" | 2단계(주문상태 맞추기)에서 비어 있는 상태를 골라 주세요 |
| 주문이 "미연결"로 남음 | 상품의 몰상품코드를 아임웹 자체상품코드와 같게 넣거나, 주문 화면에서 미연결 주문을 체크해 상품에 연결하세요 |
| 정산 미리보기에 "빠진 줄이 있습니다" | 직매입은 상품 공급가, 위탁판매는 상품 또는 계약서의 수수료율을 넣으세요 |
| 계약서 본문이 3쪽을 넘는다는 경고 | 특약사항을 줄이거나, 계약서 양식 관리에서 조항을 다듬으세요 |

## 9. 시험한 범위 (v5.0)

- 서버(구글 모형):
  - 재고형 직매입 입고 2회(1,000원·1,300원) → 출고 원가가 이동평균 1,107.14원으로 계산됨
  - 주문형 직매입: 송장발행일 자동 매입, 가상창고 같은 날 입고·출고(잔액 0), 반품완료일 마이너스 매입
  - 위탁 재고 입고·출고, 위탁 수수료 매출, 손익(상품이익·공헌이익) 값과 재고 검산 일치
  - 지급일 정산: 직매입 월 4회 11/14(토) → 11/16 지급, 위탁 월 2회 10/21 지급
  - 재고 마감 후 늦게 들어온 11/30 주문이 12/1로 들어가고 가상창고가 0으로 유지됨, 마감 풀기 후 원래 날짜로 돌아옴
  - 같은 손익 조회를 다시 열면 시트를 읽지 않음(캐시), 주문을 올려도 기본 자료 캐시는 유지
